# docs /validate_link.py

این کد برای اعتبارسنجی سخت‌گیرانه‌ی URLهای عمومی استفاده می‌شود، مخصوصاً برای endpointهای S3.  
هدف آن این است که فقط لینک‌های امن و عمومی پذیرفته شوند و آدرس‌های مشکوک، داخلی یا خصوصی رد شوند.

## رفتار کلی

این اعتبارسنجی موارد زیر را رد می‌کند:

- `localhost` و نام‌های مشابه
- IPهای داخلی، private، loopback، link-local و reserved
- دامنه‌های محلی مثل `*.local` و `*.lan`
- URLهای دارای username/password
- لینک‌هایی که فاصله، newline یا کاراکتر کنترلی دارند
- IPهای مخفی‌شده به شکل عددی یا obfuscated
- دامنه‌هایی که به IP داخلی resolve می‌شوند

---

## توابع

### `validate_link(s)`
این تابع ورودی را برای یک URL عمومی و امن بررسی می‌کند.

**کارکرد:**
- یک wrapper ساده برای اعتبارسنجی سخت‌گیرانه
- مستقیماً از `validate_public_https_url` استفاده می‌کند
- DNS resolve را هم فعال نگه می‌دارد

**خروجی:**
- `str` → لینک نرمال‌شده و امن
- `False` → اگر لینک نامعتبر یا مشکوک باشد

---

### `validate_public_https_url(value, resolve_dns=True, dns_timeout=3.0)`
این تابع اصلی اعتبارسنجی URL است.

**کارکرد:**
- مقدار ورودی را تمیز می‌کند
- فقط URLهای با scheme معتبر را می‌پذیرد
- فقط `https` را قبول می‌کند
- username/password داخل URL را رد می‌کند
- host را نرمال‌سازی می‌کند
- در صورت نیاز DNS را resolve می‌کند
- مطمئن می‌شود IPهای resolve شده عمومی باشند
- در نهایت URL نرمال‌شده را برمی‌گرداند

**نکات مهم:**
- اگر scheme نداشته باشد، به‌صورت پیش‌فرض `https://` اضافه می‌شود
- `http` عمداً پذیرفته نمی‌شود
- اگر پورت نامعتبر باشد، مقدار رد می‌شود
- مسیر، query و scheme حفظ می‌شوند ولی URL تمیز و استاندارد برگردانده می‌شود

---

### `_normalize_hostname(hostname)`
این تابع hostname را نرمال‌سازی می‌کند.

**کارکرد:**
- فاصله‌ها را حذف می‌کند
- کروشه‌های IPv6 را برمی‌دارد
- `.` انتهای دامنه را حذف می‌کند
- حروف را lowercase می‌کند
- دامنه‌های Unicode را به فرم ASCII/IDNA تبدیل می‌کند

**خروجی:**
- hostname تمیز و استاندارد
- یا `None` در صورت خطا

---

### `_is_blocked_host_without_dns(host)`
این تابع بررسی می‌کند که host بدون نیاز به DNS، مشکوک یا غیرمجاز هست یا نه.

**بررسی‌ها:**
- نام‌های بلاک‌شده مثل `localhost`
- وجود `localhost` در labelهای دامنه
- پسوندهای محلی مثل `.local`
- IP literal مستقیم
- IPهای obfuscated عددی/hex/octal
- دامنه‌هایی که IP داخلی را داخل labelهای خود پنهان کرده‌اند

اگر هرکدام از این موارد دیده شود، `True` برمی‌گرداند و host رد می‌شود.

---

### `_is_blocked_ip_literal(host)`
این تابع تشخیص می‌دهد host خودش یک IP مستقیم هست یا نه.

**کارکرد:**
- `ipaddress.ip_address` را روی host اجرا می‌کند
- اگر IP معتبر باشد، از `_is_unsafe_ip` برای بررسی امنیت آن استفاده می‌کند

---

### `_is_unsafe_ip(ip)`
این تابع unsafe بودن IP را بررسی می‌کند.

**IPهای غیرمجاز:**
- private
- loopback
- link-local
- reserved
- multicast
- unspecified

اگر هرکدام از این حالت‌ها true باشد، IP ناامن محسوب می‌شود.

---

### `_looks_like_numeric_ip_obfuscation(host)`
این تابع تشخیص می‌دهد host شبیه IP مخفی‌شده یا obfuscated هست یا نه.

**الگوهای مشکوک:**
- `2130706433`
- `017700000001`
- `0x7f000001`
- فرم‌های ترکیبی مثل `0x7f.0.0.1`

این نوع آدرس‌ها معمولاً برای پنهان‌کردن IP واقعی استفاده می‌شوند.

---

### `_contains_blocked_ipv4_labels(labels)`
این تابع بررسی می‌کند که آیا دامنه IP داخلی را داخل labelهای خودش مخفی کرده یا نه.

**مثال‌های مشکوک:**
- `127.0.0.1.nip.io`
- `192.168.1.5.sslip.io`

**کارکرد:**
- labelها را به‌صورت پنجره‌ای بررسی می‌کند
- اگر چهار بخش عددی پشت‌سرهم شبیه IP باشند، آن را IP واقعی فرض می‌کند
- اگر IP unsafe باشد، دامنه رد می‌شود

---

### `_resolves_only_to_public_ips(host, port, timeout)`
این تابع DNS را resolve می‌کند و مطمئن می‌شود همه IPهای برگشتی عمومی باشند.

**کارکرد:**
- از `socket.getaddrinfo` برای resolve استفاده می‌کند
- با `asyncio.to_thread` و `asyncio.wait_for` انجام می‌شود
- اگر DNS fail شود، `False` برمی‌گرداند
- همه IPهای resolve شده را بررسی می‌کند
- اگر حتی یکی از IPها unsafe باشد، نتیجه `False` است

**نکته:**
- اگر هیچ IP معتبری برنگردد، مقدار رد می‌شود
- این رفتار عمدی است تا endpoint مشکوک ذخیره نشود

## جمع‌بندی

این کد یک فیلتر امنیتی سخت‌گیرانه برای URLهاست و کمک می‌کند فقط لینک‌های:

- عمومی
- امن
- مبتنی بر `https`
- بدون اشاره به hostهای داخلی یا private

پذیرفته شوند.  
این کار مخصوصاً برای ذخیره و استفاده از endpointهای S3 بسیار مهم است.
